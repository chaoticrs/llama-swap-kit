# bin/audiocpp/

audio.cpp v0.9.3 (`audio-v0.9.3-bin-windows-x64-cuda12.4.zip`), unmodified. Pure C++ (ggml) engine for
130+ audio model families: TTS, voice cloning, ASR, VAD, diarization, music.

- `audiocpp_server.exe`: OpenAI-style server (`/v1/audio/speech`, `/v1/audio/transcriptions`, `/health`).
  llama-swap starts one process per model with `--config config/audiocpp/<id>.json --no-ui`; that file
  (generated by `manage.py`) holds the port, `backend` (`cpu` for always-on light models, otherwise the installed
  build: `cuda`, `vulkan` or `cpu`) and the model's family/task.
- `audiocpp_cli.exe`: one-shot CLI (`--task tts|asr --family <f> --model <gguf>`), useful for testing a model.
- `audiocpp_gguf.exe`: GGUF packaging/inspection tool.
- `model_specs/`: per-family JSON contracts (130 files) the server validates options against;
  referenced via `model_spec_override` in each generated config.
- `tools/`: upstream Python helper scripts (model manager, converters for community models). Not used by
  the stack; see its own folder_description.md.
- `ggml-cuda.dll` (~1.1 GB, CUDA kernels), `ggml*.dll`, `msvcp140*.dll`, `vcruntime140*.dll`: runtime libraries.

On a PC without NVIDIA, `scripts/setup.ps1` installs the Vulkan or CPU build of the same release here
(`ggml-vulkan.dll` instead of `ggml-cuda.dll`, no `bin/cuda` needed); this file is kept across that switch.

Runtime dependencies outside this folder (both fetched by `scripts/setup.ps1`):
- `bin/cuda/cufft64_11.dll`: the server exe imports it directly; without it the process exits immediately
  with no output (llama-swap only reports "upstream command exited prematurely").
- `bin/espeak-ng/`: Kokoro's text-to-phoneme step. This release build loads eSpeak-ng dynamically and finds it
  through `AUDIOCPP_ESPEAK_LIBRARY` / `AUDIOCPP_ESPEAK_DATA`, set in `start.ps1`. Without them every speech
  request fails with "Could not load eSpeak-ng".
