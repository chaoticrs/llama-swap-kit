# config/

Generated by `scripts/manage.py` from `models/registry.json` on every `add`/`remove`/`render`/`detect`, and
so on every `start.ps1` (absolute paths always match this folder's current location); hand edits are
overwritten. Change the registry (or re-run `add ... --force`) instead.

- `llama-swap.yaml`: llama-swap config. One entry per model with its launch command, health endpoint, idle `ttl`
  and VRAM/RAM `capacities` for the capacity router; always-on models are `preload`ed at startup with a high
  `evict_cost`. Models filling a role get `aliases` (the role names, listed in `/v1/models` via
  `includeAliasesInList`) and `useModelName` (so backends that check the name, like audio.cpp, see the real id).
  Each entry also declares `capabilities` (input/output modalities, and for audio.cpp TTS the voice ids read
  from the GGUF) so the web UI offers the model on the right playground tab and lists its voices. llama-swap watches this file and reloads it on change.
- `audiocpp/`: one audio.cpp server config per audio.cpp model (audio.cpp reads its port/backend from a file
  rather than the command line). `backend` is `cpu` for CPU models, otherwise the installed build (`cuda`,
  `vulkan` or `cpu`).
